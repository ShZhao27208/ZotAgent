# 0.4.3 — 选择已有子笔记与原生会话恢复

## 修改

- 前端显示主文献下未删除的子笔记数量，提供已有笔记下拉选择，默认保持上次归档目标。选择同步到同一主文献的各窗口，重命名、删除、新建后自动刷新。
- 归档目标在提问时固定，切换仅影响后续提问；普通子笔记保留正文，只追加结构化历史。新设备缺少本地绑定时优先识别已有归档笔记，避免直接另建重复归档。
- 新归档记录的 Agent、问题/回答标题、文献和时间标签使用原生笔记支持的颜色、加粗、底纹；保持归档边界及 Markdown 导出可读性，不批量修改旧正文。
- Claude Code 原生终端使用 `--resume <会话ID>` 接续结构化会话；Claude/Codex 恢复使用记录中的实际工作目录。
- 原生终端增加折叠的会话信息：ID、实际环境、CLI、目录和恢复方法。结构化任务进行时禁止并行打开同一会话，终端模式下禁止在隐藏的结构化界面发送。Runtime 也检查同一会话是否正被其他请求/终端占用。
- Runtime 协议为 4，避免更新后复用没有恢复逻辑的旧服务；版本缓存目录升为 0.4.3。

## 诊断结论

- 用户确认先点击了停止，再打开 Codex 终端。截图里的 `Conversation interrupted` 与手动停止一致，不认定为插件注入失败。
- 只读检查对应本地 Codex 会话：来源为 `exec`，CLI 0.156.1，目录 `/home/shzhao`，保存了约 10.65 万字符的用户输入，包含文献上下文和提问标记，没有已完成回答。没有复制正文或凭据到本报告。
- 本机 `codex resume --help` 与 OpenAI 官方文档均说明 `--include-non-interactive` 可包含非交互会话；`--all` 取消目录过滤。恢复列表查不到不能推断历史未保存。
- 本机 Claude 2.1.282 帮助支持按 ID 恢复；所检查的近期原生记录存在用户输入和回答。旧插件交互入口不传 ID 是明确缺陷，文件大小本身不能证明 PDF 全文已注入。
- 官方依据：https://developers.openai.com/codex/cli/reference/#codex-resume 。

## 验证与边界

- 完整回归：146 项，145 通过、1 项 Windows CMD 专用测试跳过。新增集成测试只调用临时目录下的模拟 CLI，验证准确 ID 恢复、实际目录及结构化/PTY 相互排斥。
- 笔记测试覆盖跨窗口选择、旧任务目标保持、普通正文保留、无本地映射时重新发现归档、删除/其他主文献笔记拒绝、Notifier 刷新、颜色标记与 Markdown 导出。
- 不下载浏览器、不启动独立 Zotero 窗口、不发起真实模型请求。真实 Claude TUI 内容显示、Zotero 下拉交互及新笔记样式仍需用户本机验收。
- 原生终端输入不自动归档；OpenCode 仍打开独立交互界面，不宣称本轮实现其原生会话恢复。恢复历史不等于模型已成功处理全部输入。

## 本机验收

1. 同一文献打开两个窗口，下拉选择一个已有普通子笔记，发送简短问题；确认两个窗口目标一致、旧正文保留、新记录追加到所选笔记。
2. 回答中切换目标，确认旧问题结束后仍存到旧笔记；下一问题存到新笔记。检查计数与重命名刷新，以及 Agent/文献/时间的视觉区分。
3. Claude/Codex 对话结束或停止后打开原生终端，展开会话信息核对 ID、目录和环境。Claude 应恢复对应内容，Codex 手动停止的历史可保留中断提示。
4. 在相同环境运行 `codex resume --all --include-non-interactive`，或直接按显示的会话 ID 恢复。
